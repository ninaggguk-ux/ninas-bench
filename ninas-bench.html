About these metrics
  • TTFT (time to first token) — from request start until the first generated token. Includes prompt processing (prefill) and, on a cold server, model load time — which is why the warm-up pass matters.
  • Generation tok/s — output tokens per second during decoding. Computed from server-reported token counts when available; otherwise estimated from text length and marked est.
  • Prompt tok/s — how fast the model digests your input prompt (only reported by some servers, e.g. Ollama).
  • Score 1–5 — quality rating: manual ★ from you, or auto-judge output (marked judge). Judge scores are approximate and biased if the model judges itself.
  • Runs execute sequentially so models never contend for CPU/GPU — that's what makes the numbers comparable.

Everything runs in your browser and is saved locally (localStorage). No data leaves your machine except to your own model server. Reasoning models emit “thinking” tokens before answering — those are included in timing, shown collapsed under each output.

📖 Nina`s Bench — Help & guide

Getting started

Nina`s Bench measures how your local models actually perform on the machine you're sitting at — then tells you which model (and which quant) to keep. Four steps:

  1. Connect to your local server (LM Studio or Ollama) in section 1.
  2. Select the models & quants you want to compare — several quants of the same base model is the classic setup.
  3. Check the suite — the default tasks cover a quick fact, a math trap, code and instruction-following. Edit or add your own.
  4. Run and read the recommendation banner at the top of the results.
Tip: keep warm-up pass on — it loads each model's weights once with a tiny prompt, so your TTFT numbers measure real inference instead of cold-start.

Server setup

Nina`s Bench talks to your server through the normal browser API — nothing to install.

ProviderDefault URLNotes
LM Studio / OpenAI-compatiblehttp://localhost:1234/v1In LM Studio: Developer tab → Start server. If the browser is blocked by CORS, enable it in the server settings.
Ollamahttp://localhost:11434Start ollama serve. No /v1 suffix. Ollama reports prompt tok/s, so you get more metrics.

The API key field is optional — local servers usually don't need one. Add it only if your server asks for a Bearer token.

“Could not connect (…)”? The three usual causes: the server isn't running, the URL/port is wrong, or the browser is blocked by CORS. Open devtools (F12) — the network error tells you which one it is.

Models & quants

Every entry in the list is one model + one quant. To compare quantization quality head-to-head, select several quants of the same base model (e.g. qwen3-4b-q4_k_m and qwen3-4b-q8_0) — the results banner then recommends the best quant per family.

  • Select all / Clear selection (or press A / N) toggle every entry at once.
  • Ollama shows size and quant level as a tag next to the name; OpenAI-compatible servers show whatever they report.
  • Your selection is remembered between sessions.

Benchmark suite & settings

Tasks — each task is a prompt you can edit, add or remove (the checkbox includes it in the run). Answers are capped by the max-token limit so every model gets the same budget and runs stay fast.

SettingWhat it does
Max tokens per answerHard cap on each answer. Keep it the same for every model — comparability matters more than long answers.
Runs per model × task1 = fast, 3 = most stable (results are averaged). Use 2–3 when deciding between close models.
Temperature0.2 by default — low enough for reproducible answers. Set 0 for coding tasks; raise it to test creative output.
Warm-up passSends a tiny prompt to each model first and excludes that call from the results. Recommended: without it, the first task includes cold model load time.

Auto-scoring with a judge model

Tick Auto-score quality with a judge model and pick a judge from the dropdown. After every run, the judge reads each output and grades it 1–5 as strict JSON, so you get quality scores without clicking stars yourself.

  • Use a different — ideally stronger — model as judge when possible; a model judging itself is biased in its own favour.
  • Judging adds one extra API call per output, so it lengthens the run.
  • Manual ★ ratings always override the judge score.

Running a benchmark

Click Run benchmark. The progress bar and status line follow every step: warm-up (if enabled), then each model × task × run, then judging (if enabled).

  • Runs execute sequentially, so models never contend for CPU/GPU — that's what makes the numbers comparable.
  • Cancel (or press C) stops at the next boundary and keeps everything measured so far.
  • Reasoning models emit “thinking” tokens before answering; those are included in timing and shown collapsed under each output.

Reading the results

The banner is the headline: with scores it recommends quality-first (then speed); without scores it names the fastest model. When you've benchmarked several quants of one base, it lists the best quant per family.

  • Summary table — per-model averages: runs, best TTFT, avg generation speed, prompt speed, tokens out, score. The top row is highlighted as “best pick”.
  • Charts — generation speed (higher is better) and time-to-first-token (lower is better).
  • All runs table — click any column header to sort; empty values always sink to the bottom.
  • Outputs grid — the actual answers, grouped by task. Rate them with ★ (manual score overrides auto-judge), copy them, or expand the collapsed thinking of reasoning models.

Export CSV / JSON saves the whole results set for spreadsheets or archiving. Clear results wipes the runs (settings survive).

Troubleshooting

  • “Could not connect (timed out / Failed to fetch)” — server not running, wrong URL/port, or CORS. LM Studio: enable CORS in the Developer → Server settings. Ollama on another machine: set OLLAMA_ORIGINS.
  • “Connected, but no models found” — the endpoint is reachable but returned an empty list; check you're pointing at the right server.
  • First run looks slow — that's model load. Keep warm-up on and compare runs 2+.
  • “est” tags everywhere — your server doesn't report token counts in the stream. Speeds are still measured from wall time; token counts are approximated at ~4 chars/token.
  • Judge failed / timeout — the judge call has a 3-minute timeout; small models on slow CPUs can exceed it. Retry or pick a faster judge.
  • Numbers drift between runs — close other GPU-hungry apps (browsers with WebGL, video), use runs = 2–3 and read the averages.

Data & privacy

Everything runs in your browser. Settings, task edits and results are stored in localStorage under the key modelBench.v1 — nothing is uploaded anywhere except to your own model server.

  • Clear results removes runs but keeps settings; clearing browser site data resets everything.
  • Export JSON is a full backup of settings + results if you want them across machines.
